# Тестирование локальных OCR моделей для AISmetchikV9

**Дата:** 2026-06-16
**Тестовый документ:** Смета с таблицей (1 страница, английский текст, структурированные данные)
**Система:** macOS ARM64 (Apple Silicon), Node.js v25.9.0, Python 3.14

---

## Результаты тестирования

### 1. Tesseract.js ✅ РАБОТАЕТ

| Параметр | Значение |
|----------|----------|
| **Пакет** | `tesseract.js` (npm) + `pdfjs-dist` + `canvas` |
| **Установка** | `npm install tesseract.js pdfjs-dist canvas` |
| **Скорость (OCR)** | **467ms** на страницу |
| **Скорость (с конвертацией PDF)** | **603ms** на страницу |
| **Точность (confidence)** | **92.0%** |
| **Размер модели** | ~4MB (eng), ~23MB (rus traineddata) |
| **Русский язык** | ✅ Поддерживается (отдельный traineddata файл) |
| **Зависимости** | Чистый JavaScript (WASM), не требует Python/GPU |
| **Качество текста** | Отличное — все символы, числа, структура распознаны корректно |

**Пример вывода:**
```
SMETA #12345
Object: Residential building, Pushkina st. 10
Customer: OOO StroyInvest
1. Cable VVGng 3x2.5 - 500m - 120rub - 60000rub
2. Electrical panel - 3pcs - 4500rub - 13500rub
...
TOTAL: 103450 rub
```

**Плюсы:**
- Чистый JS, работает в Node.js без нативных зависимостей
- Маленький размер модели
- Хорошее качество для печатного текста
- Поддержка 100+ языков
- Активное сообщество

**Минусы:**
- Медленнее cloud API
- Требует конвертации PDF → изображение
- Хуже работает с рукописным текстом и сложными таблицами

### 2. PaddleOCR (paddleocr npm) ⚠️ РАБОТАЕТ С БАГОМ

| Параметр | Значение |
|----------|----------|
| **Пакет** | `paddleocr` + `onnxruntime-node` + `fast-png` |
| **Установка** | `npm install paddleocr onnxruntime-node fast-png` |
| **Скорость (OCR)** | **2692ms** на страницу |
| **Скорость (с загрузкой моделей)** | **2780ms** на страницу |
| **Точность** | ⚠️ **Систематическая ошибка** — все символы смещены на +1 |
| **Размер модели** | ~90MB (det: 82MB + rec: 7.5MB + dict) |
| **Русский язык** | ⚠️ Есть модель "eslav" (Russian, Bulgarian, Ukrainian, Belarusian), 81.6% accuracy |
| **Зависимости** | ONNX Runtime (Node.js binding) |
| **Качество текста** | ❌ НЕПРИЕМЛЕМО — текст "SMETA" → "TNFUB", все буквы сдвинуты |

**Пример вывода (с багом):**
```
TNFUB$23456          ← вместо "SMETA #12345"
Pckfdu;Sftjefoujbmcvjmejoh-Qvtiljobtu/21  ← вместо "Object: Residential building..."
```

**Анализ проблемы:**
Символы сдвинуты ровно на 1 позицию в Unicode (T→S, N→M, F→E и т.д.). Это указывает на ошибку в словаре символов (dict.txt) при конвертации модели из PaddlePaddle в ONNX формат.

**Плюсы:**
- Работает в Node.js через onnxruntime-node
- Хорошая архитектура (detection + recognition pipeline)
- Поддержка 80+ языков
- Есть модели для русского языка

**Минусы:**
- ❌ **Критический баг** в ONNX конвертации — символы сдвинуты
- Большой размер модели (90MB)
- Медленнее Tesseract
- Требует ручной загрузки ONNX моделей
- Нет встроенного PDF парсера

### 3. Surya OCR ❌ НЕ ЗАПУСТИЛСЯ

| Параметр | Значение |
|----------|----------|
| **Пакет** | `surya-ocr` (pip) |
| **Установка** | `pip install surya-ocr` + `brew install llama.cpp` |
| **Скорость** | ❌ **Таймаут** — не удалось завершить за 2 минуты |
| **Размер модели** | **~650MB** (650M параметров) |
| **Русский язык** | ✅ Поддерживается (91 язык, 87.2% accuracy) |
| **Зависимости** | Python + PyTorch + llama.cpp + ~650MB моделей |
| **Качество текста** | Неизвестно — не удалось запустить |

**Проблемы:**
1. **Требует Python** — не интегрируется напрямую в Node.js
2. **Требует llama.cpp** — отдельная установка через brew
3. **Огромные модели** — 650MB загрузка + 4GB+ RAM
4. **Медленный на CPU** — таймаут даже на Apple Silicon
5. **Нужен GPU для приемлемой скорости** — 5 pages/s только на RTX 5090

**Плюсы:**
- Лучшее качество по бенчмаркам (83.3% на olmOCR-bench)
- Layout analysis + table recognition
- Поддержка 90+ языков

**Минусы:**
- Непригоден для локального запуска без GPU
- Слишком тяжёлый для серверной интеграции
- Python-only, несовместим с Node.js stack

## Рекомендация

### ✅ Рекомендуется: Tesseract.js

**Tesseract.js — единственный жизнеспособный вариант** для локальной OCR в AISmetchikV9:

1. **Работает** — проверено, 92% confidence
2. **Быстро** — ~500ms на страницу
3. **Легко** — чистый JS, npm install и готово
4. **Маленько** — 4-23MB на модель
5. **Русский язык** — поддерживается через `rus` traineddata

### ⚠️ PaddleOCR — требует фикса
Проблема со сдвигом символов — это баг в ONNX конвертации модели. Возможно, нужна другая версия модели или ручная коррекция словаря. Не рекомендуется для production до исправления.

### ❌ Surya — отказ
Слишком тяжёлый, требует Python + GPU. Непригоден для локальной интеграции в Node.js проект.

## Отказ от идеи полной замены cloud API

**Вердикт: Tesseract.js можно использовать как fallback, но не как замену cloud API.**

Причины:
1. **Качество** — Tesseract 92% vs cloud API 98%+ на сложных документах
2. **Сложные таблицы** — локальные модели хуже с таблицами и структурированными данными
3. **Специальные символы** — может пропускать/искажать спецсимволы в сметах
4. **Скорость** — cloud API быстрее для пакетной обработки

**Рекомендуемая стратегия:**
- Использовать Tesseract.js как **fallback** когда cloud API недоступен
- Основной путь — cloud API (OpenRouter)
- Локальная OCR — для офлайн-режима или экономии бюджета
