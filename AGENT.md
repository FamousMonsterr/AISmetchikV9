# Баланс / Billing UI шаблон

## Структура блока
- Две карточки в первой строке:
  - **Тариф**: заголовок, бэйдж плана, короткое описание, CTA (например, “Перейти на PRO”).
  - **Баланс**: крупное число кредитов, подпись, опционально бонусы и срок действия бонусов.
- Далее секция “Пополнить баланс” в виде сетки карточек пакетов (цена, перечень фич, выгода, CTA “Пополнить”).
- Карточка S3-хранилища: список преимуществ + CTA.
- Карточка Enterprise-предложения: градиентный фон, цена/условия, список фич, CTA “Обсудить”.
- История счетов (InvoiceHistory) и мелкий дисклеймер.

## Вёрстка и тоны
- Использовать `Card`, `CardHeader`, `CardContent`, `CardFooter`, `Badge`, `Button`.
- Грид: `grid-cols-1 lg:grid-cols-2` для верхних карточек, `md:grid-cols-2 lg:grid-cols-3` для пакетов.
- Бонусы/статусы — зелёный текст, основной план — бэйдж с акцентным цветом.
- CTA “Пополнить” на всю ширину карточки пакета, популярные помечать `border-2 border-primary`.

## Поведение
- Клики по пакету открывают диалог оплаты (PurchaseCreditsDialog) с выбранным пакетом.
- Enterprise: подставлять `enterpriseEmail` из настроек, fallback на support.
- Если есть бонусные кредиты и срок их действия — показывать ниже основного баланса.

## Компоненты/файлы
- Реализация: `src/app/dashboard/billing/page.tsx`.
- Диалоги: `src/components/PurchaseCreditsDialog.tsx`, `src/components/InvoiceHistory.tsx`.

Используйте эту схему как эталон для новых экранов пополнения/планов.

## Группы и синхронизация (калькулятор)
- В режиме группы есть вкладки проектов и быстрый синхро‑диалог по совпадающим названиям.
- Кнопка “Синхронизировать сейчас” открывает диалог конфликтов цен и применяет выбранные цены ко всей группе.
- В диалоге синхронизации можно применить выбранную цену либо ко всей группе, либо только к текущей вкладке.
- В группе добавление проекта вынесено в компактную вкладку “+” (стандартный анализ + списание кредита).
- ZIP‑выгрузка “вся группа” — отдельные документы на каждый проект с расширенными настройками счета.
- В выгрузке группы есть режим “Один файл”: КП с сводной страницей в начале (PDF) или сводным листом в Excel; договор — единый файл с приложениями.
- В режиме ZIP можно собрать архив по проектам или архив с набором документов (например, счет + договор).
- При включенном групповом режиме AI‑распределение цен работает сразу по всей группе как по одной спецификации; при выключенном — только по активной вкладке.
- История действий хранит 10 последних записей, включая AI‑правки и применение цен; AI‑действия сохраняются в БД и доступны после перезахода (undo тоже сохраняется).

## Групповой режим (переключатель)
- В группе добавлен тумблер “Групповая работа”: включено — действия (AI, документы, синхронизация) применяются к группе; выключено — работа только с выбранной вкладкой.
- Визуальный тон карточки группы меняется при включенном режиме (мягкий, с поддержкой светлой/темной темы), с тонкими hover/active подсветками и приглушенными цветами текста.
- Коэффициент сложности масштабирует цену монтажа каждой позиции (по текущей вкладке или по группе при активном тумблере).
- Сгруппировать проекты можно на Free, но редактирование группы доступно только PRO+ (через триал при первой попытке).
- AI-ценообразование и поиск пропущенных позиций в группе применяются ко всем сметам при включенном тумблере групповой работы.
- Добавлен блок “AI-правки проекта” с голосовым/текстовым вводом и JSON-применением изменений к смете.
- В групповом режиме AI‑правки прогоняются по всей группе (единый набор правок применяется ко всем сметам).

## AI модели и апгрейд
- Выбор модели AI доступен только на тарифах Business/Enterprise.
- На Free/PRO названия моделей скрыты: показывается текущая модель (по тарифу) и бейдж Business без кнопки “Запросить/Сменить”.
- Для Free/PRO возможен A/B‑тест моделей: если в конфиге задано несколько моделей, пользователю показывается выбор предпочтительной (PlanModelPreference).
- Админ управляет моделями по тарифам в `src/lib/ai-config.json` → `planModels` (Free/PRO: default + abTestModels, Business/Enterprise: availableModels).
- Для Business/Enterprise нет триала: апгрейд только по заявке (email из настроек).
- В диалоге приватной базы цен есть кнопка подключения S3; она помечена как Business и ведет к заявке.
- Голосовой ввод в AI‑правках использует модель, выбранную как “Голос” в админ‑панели (транскрипция через AI).

## Тарифы и доступы (единые правила)
- **Free**: базовый анализ, создание групп, работа с одной сметой; без приватной базы цен и без группового редактирования.
- **PRO+ (PRO/Business/Enterprise)**: групповое редактирование, синхронизация по названию, документы группы, AI‑правки, расширенный калькулятор, приватная база цен.
- **Business/Enterprise**: все PRO + расширенные лимиты и корпоративные опции.
- В Free все PRO-функции имеют приписку “(PRO)”, в PRO+ кнопки подсвечиваются золотисто‑бронзовым акцентом.
- Для Business‑функций используются бейдж “Business” и синие акцентные стили; на Business/Enterprise эти кнопки отображаются без бейджа, но с фирменным синим тоном.
- Бейджи тарифов унифицированы через `src/components/PlanBadge.tsx`.

## Документы и формы
- КП по группе формируется в одном PDF: каждая вкладка начинается с новой страницы.
- Договор подряда для группы формирует одно тело договора и отдельные приложения по каждой вкладке (Приложение №1…N).
- Счет: поддерживает авансовый/финальный тип, основание (проект/договор), ввод номера и даты договора, настройку формулировки, опциональный акт выполненных работ.
- Для финального счета можно сформировать акт выполненных работ в составе выгрузки.
- Добавлены формы: Акт выполненных работ, КС‑2, КС‑3, КС‑6а (поддерживают групповой режим).

## Навигация и чат
- Значок уведомлений расположен в навигационной панели рядом с переключателем темы (без дублей в других местах).
- Чат поддержки доступен как плавающая кнопка и открывается без перехода на отдельную страницу.
- Чат поддержки ограничен по высоте и не растягивает страницу; история прокручивается внутри блока.

## S3 бакеты по назначению
- `analysis` (по умолчанию): основной бакет из настроек S3 (`s3BucketName`) для первичного анализа и кэша.
- `avatars`: отдельный бакет для аватаров (`s3AvatarBucketName`), fallback на `s3PersonalBucketName` или основной.
- `user_docs`: документы пользователя (счета, чеки, подписи, печати) — `s3UserDocsBucketName`.
- `project_docs`: документы проектов (КП/договоры/акты) — `s3ProjectDocsBucketName`.
- Для каждого назначения можно указать свой S3 preset (`s3AvatarPresetId`, `s3UserDocsPresetId`, `s3ProjectDocsPresetId`).
- В админке: `S3 Settings` → блок “Назначение бакетов” (выбор, создание и назначение).

## Аватар
- В профиле загрузка аватара проходит через простую обрезку (crop) с выбором области.
- Компонент: `src/components/AvatarCropDialog.tsx`. Итог сохраняется как квадратный JPEG и отправляется в S3 (`avatars` bucket).

## Категории позиций (AI и UI)
- В проект добавлен отдельный тип позиции `cable_support` — **кабеленесущая конструкция**.
- Актуальный набор типов: `device`, `cable`, `cable_support`, `consumable`, `other`.
- Правила классификации:
- `device`: приборы и оборудование (прибор, датчик, устройство, сервер, камера, контроллер, считыватель и т.д.).
- `cable`: кабельная продукция (кабель/провод, витая пара, ШВВП, КПСНГ, UTP/FTP, сечение/парность).
- `cable_support`: то, в чем или по чему идет кабель (гофра, труба ПВХ/ПНД, металлорукав, кабель-канал, лоток, короб).
- `consumable`: расходные материалы и крепеж (стяжки, дюбеля, саморезы, мастика, огнезащита, перчатки и т.п.).
- `other`: все, что не удалось уверенно классифицировать.
